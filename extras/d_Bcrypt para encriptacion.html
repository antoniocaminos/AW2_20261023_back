El problema del texto plano

Hasta ahora guardábamos las contraseñas tal cual las escribía el usuario. Esto es un peligro enorme.

❌ Hackeo

Si acceden al JSON, ven todas las contraseñas.

❌ El Admin

El dueño de la base puede leer tu contraseña.

❌ Efecto dominó

Si usás la misma pass en otro sitio, te hackean ahí también.

// ❌ ASÍ NO SE HACE NUNCA { "email": "ana@test.com", "pass": "contrasenia1234" // ¡Texto plano! }

¿Qué es un Hash? (La Licuadora)

El Hashing es una función matemática de un solo sentido: convierte tu contraseña en un texto ilegible que jamás se puede revertir.

🍎 Analogía: Metés una manzana en la licuadora y sale un licuado verde. Jamás vas a poder volver a armar la manzana entera desde el licuado.
Contraseña Original (Manzana)
"contrasenia1234"
Después del Hash (Licuado)
"$2a$10$N9qo8uLOickgx2ZMRZoMye..."

El Secreto del "Salt" (La Sal)

Si dos usuarios usan la misma contraseña ("123456"), un algoritmo de hash común generaría el mismo resultado. Si un hacker tiene una tabla de hashes conocidos (Rainbow Table), puede descubrir ambas contraseñas al mismo tiempo.

Bcrypt resuelve esto automáticamente con el Salt. Le agrega un texto aleatorio a la contraseña antes de hashearla. Aunque dos personas usen "123456", sus hashes serán completamente distintos.

🧂 Analogía: Es como cocinar. Si dos personas hacen el mismo puré de papas, saben igual. Pero si a uno le echás una pizca de sal y pimienta, y al otro le echás orégano, los platos finales saben distinto. El Salt es esa "pizca" única que hace que cada contraseña, incluso si es igual, sea única al hashearse.
¿Dónde se guarda el Salt?

En Bcrypt, el Salt viene incluido dentro del mismo string del hash.

// El string del hash de Bcrypt tiene 3 partes: $2a$10$N9qo8uLOickgx2ZMRZoMye... │ │ └── El hash + el Salt (generado aleatoriamente) │ └── Rondas de hashing (10) └── Versión del algoritmo

Manos a la obra: Instalando Bcrypt

Para empezar a hashear, necesitamos instalar la librería. Vamos a usar bcryptjs (es puro JavaScript, funciona en Windows sin problemas).

  1. 1 Abrir la terminal en la carpeta del backend.
  2. 2 Instalar la librería: ejecutamos el comando de npm.
  3. 3 Importar en el controller: lo llamamos en la parte superior del archivo.
1. En la Terminal
# Instalamos bcryptjs npm install bcryptjs
2. En el Controller
// usuarios.controller.js import bcrypt from 'bcryptjs';

¿Qué cambió exactamente en el código?

Así quedaron nuestras funciones de Login y Crear Usuario.

❌ Antes (Login)
const usuario = listaUsuarios.find( u => u.email === email && u.pass === pass // Comparación directa );
✅ Ahora (Login)
const usuario = listaUsuarios.find( u => u.email === email ); const passValida = await bcrypt.compare( pass, usuario.pass );
❌ Antes (Crear Usuario)
const nuevoUsuario = { id: nuevoId, email: email, pass: pass // ¡Texto plano! };
✅ Ahora (Crear Usuario)
const passHasheada = await bcrypt.hash(pass, 10); const nuevoUsuario = { id: nuevoId, email: email, pass: passHasheada // 👈 Seguro };

Bcrypt: Pros y Contras

✅ PROS ❌ CONTRAS
🔒 Diseñado específicamente para contraseñas (lento a propósito). ⏳ Consume más CPU que otros algoritmos (por diseño).
🧂 Salting automático: dos usuarios con misma pass = hashes distintos. 📦 Requiere instalar una librería extra (bcryptjs).
🛡️ Resistente a ataques de fuerza bruta (las rondas de sal hacen lento cada intento). 🧠 No sirve para encriptar datos (solo para hashear contraseñas).
🏆 Estándar de la industria (lo usan miles de empresas). 🔄 No se puede "recuperar" la pass original (si se olvida, se resetea).

¿Qué pasa con los usuarios viejos?

Si ya tenías usuarios guardados con contraseñas en texto plano, no podés borrarlos. La solución es crear un script de migración que lea el JSON, hashee las contraseñas viejas y las guarde de nuevo.

El script que armamos en clase: Detecta si la contraseña no empieza con $2a$. Si es así, significa que está en texto plano. La hashea y actualiza el archivo. Lo ejecutás con node scripts/migrarPasswords.js y listo. Tus usuarios viejos pueden loguearse de nuevo sin problema.
