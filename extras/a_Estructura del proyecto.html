¿Qué hay en cada carpeta?

🚪 index.js

Es el punto de entrada. Crea la app de Express, registra los middlewares globales (express.json(), logger), monta el router de usuarios bajo /usuarios y levanta el servidor con app.listen(). No tiene lógica de negocio.

🛣️ routes/

Define qué URL responde a qué función. Es un "índice": POST /login, GET /, GET /:id, etc. No tiene lógica, sólo pega la URL con el controller correspondiente.

🧠 controllers/

Contiene la lógica del CRUD: leer el JSON, validar campos, calcular el nuevo id, guardar, responder con el status correcto (200, 201, 400, 401, 404, 409, 500).

🧩 middlewares/

Funciones que se ejecutan entre la request y la respuesta: loguear, validar body, chequear token, manejar errores. Reusables en todas las rutas.

🗄️ data/

Los datos persistentes. En este proyecto es un JSON que hace de base de datos. Cuando migres a MongoDB o SQL, esta carpeta desaparece (o cambia).

⚙️ .env

Variables de entorno (puerto, claves, URLs). Nunca se sube a Git. Se lee con dotenv y se accede vía process.env.PORT.

¿Por qué el orden importa?

Express ejecuta en cascada: cada app.use() que registrás corre en el orden en que fue declarado. Si lo pones al revés, o no llega la request, o el middleware nunca se ejecuta.

  1. 1 Imports — todo lo que se usa debe estar importado primero.
  2. 2 dotenv.config() — cargar variables antes de leer process.env.
  3. 3 const app = express() — crear la app antes de configurarla.
  4. 4 Middlewares globales (express.json(), logger) — deben estar activos antes de las rutas que los usan.
  5. 5 Rutas (app.get('/'), app.use('/usuarios', ...)) — después de los middlewares.
  6. 6 app.listen() — al final. Recién cuando todo está definido, el server empieza a escuchar.
Regla práctica: en index.js, la última línea siempre debe ser app.listen(). Todo lo demás va antes.

Flujo de una request

Cliente (Postman) index.js → express.json() middleware logger routes/usuarios.routes.js controllers/usuarios.controller.js data/usuarios.json
Y la respuesta vuelve por el mismo camino: controller → router → cliente.

Una carpeta, una responsabilidad

Carpeta / Archivo Responsabilidad ¿Qué NO va acá?
index.js Arrancar el server y montar todo Lógica de negocio, validaciones
routes/ Mapear URL + método → controller Leer archivos, validar, calcular ids
controllers/ Lógica de negocio (CRUD, validaciones) Definir rutas o montar middlewares globales
middlewares/ Funciones que corren antes del controller Lógica de negocio específica de un endpoint
data/ Persistencia cruda (JSON, seeds) Lógica, validaciones, transformaciones
